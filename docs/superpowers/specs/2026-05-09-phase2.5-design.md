- 日期：2026-05-09

## 1. 目標與範圍

把規劃心理模型從「pick 起終點 + auto path + auto dayBreak」升級為「逐日明確目標 + 中途加爬點 + 回程開關」，讓使用者可以表達「Day 1 到山屋、Day 2 攻幾個峰、Day 3 撤退」這類真實登山計畫。

### 在範圍內

- **DailyPlan 資料模型**：每日獨立 `{ endNodeId, endType, hutId?, viaNodeIds[] }`
- **回到起點 toggle**：`returnToStart` 預設 on，自動處理回程
- **DailyPlanResolver service**：把 `dailyPlans` 解出 `nodeSequence + dayBreaks`，驅動 Phase 1+2 視圖
- **B3 摺疊日列表 UI**：右側 panel 是 DailyPlanEditor，每日一張 DayCard 可折疊／展開
- **M1 popup**：地圖點選節點 → popup「當作目標 / 加為加爬點 / 取消」
- **NodePicker 元件**：依節點 category 分群的下拉選單
- **Preset 修補**：`viaNodeIds` 接通到應用流程（Phase 1 bug）
- **Migration**：Dexie v1 → v2 自動 upgrade，舊 plan 反推 dailyPlans
- **DayBreaker deprecated**：保留檔案 + 測試但不再被呼叫；planStore 移除 `autoSuggestDayBreaks`

### 不在範圍內

- 縱走多端點（A 點上、B 點下）— Phase 5
- 自訂中繼點（非節點圖上的點）— Phase 5
- 多日同時展開比較 — 暫一次只能展開一日
- Build-time validate-routes.ts — Phase 4
- 路徑重新規劃的「替代路徑建議」功能 — 不做

### 設計原則

- **Plan.dailyPlans 為「真相」，nodeSequence/dayBreaks 為 derived**：UI 編輯只動 dailyPlans，其他自動同步
- **Phase 1+2 元件零修改**：TableView / GanttView / ElevationView / PrintLayout / TimeCalculator / ScheduleGrouper / SegmentColor / GearSuggester 全部沿用，靠 derived 餵資料
- **Migration 一次性**：升級時自動補 dailyPlans，之後使用者編輯走新 flow
- **Popup 用 Vue Teleport**：避免動態 addEventListener 的 leak 風險，型別乾淨

### 6.2 演算法

```
let dayStart = startNodeId
let allNodes: string[] = []
let allWarnings: string[] = []
let days: DayResolution[] = []
let dayBreaks: DayBreak[] = []

for (i, daily) in dailyPlans.entries():
  // (1) returnToStart 改寫最後一日
  let effectiveEnd = daily.endNodeId
  let effectiveVia = daily.viaNodeIds
  if i === dailyPlans.length - 1 && returnToStart && daily.endNodeId !== startNodeId:
    effectiveEnd = startNodeId
    effectiveVia = [...daily.viaNodeIds, daily.endNodeId]

  // (2) 解該日路徑（用既有 PathResolver）
  const path = PathResolver.resolvePath({
    route, startNodeId: dayStart, endNodeId: effectiveEnd, viaNodeIds: effectiveVia,
  })
  if path.warnings.includes('no_path'):
    allWarnings.push(`day_${i+1}_unreachable`)
    days.push({ dayIndex: i+1, startNodeId: dayStart, pathNodeIds: [], segments: [], warnings: ['no_path'] })
    // 不更新 dayStart, 跳過 nodeSequence 累積
    continue

  // (3) 累積該日 path
  const pathIds = path.forward
  days.push({ dayIndex: i+1, startNodeId: dayStart, pathNodeIds: pathIds, segments: makeSegments(pathIds), warnings: [] })
  if allNodes.length === 0:
    allNodes.push(...pathIds)
  else:
    // 去除接點重複（前一日 end == 本日 start）
    if allNodes[allNodes.length-1] === pathIds[0]:
      allNodes.push(...pathIds.slice(1))
    else:
      allNodes.push(...pathIds)
      allWarnings.push(`day_${i+1}_disjoint`)  // 理論上不該發生

  // (4) 加 dayBreak（除最後一日外）
  if i < dailyPlans.length - 1:
    dayBreaks.push({
      afterNodeId: effectiveEnd,
      type: daily.endType,
      hutId: daily.hutId,
    })

  dayStart = effectiveEnd

return { days, nodeSequence: allNodes, dayBreaks, warnings: allWarnings }
```

### 6.4 反推演算法

```
const dailyPlans: DailyPlan[] = []
let prevEnd = legacy.startNodeId
for (brk) in legacy.dayBreaks:
  dailyPlans.push({
    endNodeId: brk.afterNodeId,
    endType: brk.type,
    hutId: brk.hutId,
    viaNodeIds: [],          // 無法從 nodeSequence 還原原始意圖
  })
  prevEnd = brk.afterNodeId

// 最後一日：endNodeId = nodeSequence 結尾
const finalEnd = legacy.nodeSequence[legacy.nodeSequence.length - 1]
dailyPlans.push({
  endNodeId: finalEnd,
  endType: 'manual',
  viaNodeIds: [],
})

// returnToStart 推斷：最後 endNodeId === legacy.startNodeId
const returnToStart = finalEnd === legacy.startNodeId

return { dailyPlans, returnToStart }
```

## 8. RoutesListView 與 Preset 應用

### `derivePresetDailyPlans` 函式

放在 `RoutesListView.vue` 或抽到 utility：

```ts
function derivePresetDailyPlans(preset: RoutePreset, route: Route): DailyPlan[] {
  const breaks = preset.suggestedDayBreaks ?? [];
  if (breaks.length === 0) {
    return [{
      endNodeId: preset.endNodeId,
      endType: 'manual',
      viaNodeIds: preset.viaNodeIds ?? [],
    }];
  }
  const days: DailyPlan[] = breaks.map((b) => ({
    endNodeId: b.atNodeId,
    endType: b.type,
    hutId: route.nodes.find((n) => n.id === b.atNodeId)?.hutId ?? undefined,
    viaNodeIds: [],
  }));
  const usedVias = new Set(breaks.map((b) => b.atNodeId));
  const remainingVias = (preset.viaNodeIds ?? []).filter((v) => !usedVias.has(v));
  days.push({
    endNodeId: preset.endNodeId,
    endType: 'manual',
    viaNodeIds: remainingVias,
  });
  return days;
}

function applyPreset(routeId: string, presetId: string) {
  const route = routesStore.getById(routeId);
  if (!route) return;
  const preset = route.presets.find((p) => p.id === presetId);
  if (!preset) return;
  planStore.draft = {
    routeId,
    startNodeId: preset.startNodeId,
    returnToStart: true,
    dailyPlans: derivePresetDailyPlans(preset, route),
    paceMultiplier: settings.defaultPaceMultiplier,
  };
  router.push({ name: 'map', query: { route: routeId, preset: presetId } });
}
```

## 10. 邊界條件處理

| 情境 | 對策 |
|---|---|
| `dailyPlans.length === 0` | 編輯器禁存（儲存按鈕 disabled），UI 提示「至少要有一天」 |
| 單日 + returnToStart=true 且 endNodeId=startNodeId | 不改寫，直接 PathResolver 解 O 型 |
| 單日 + returnToStart=true 且 endNodeId≠startNodeId | 改寫：via 加原 endNode，end=start |
| Day N 起點到 Day N target 不連通 | warning `day_n_unreachable`；DayCard 顯示 ⚠；resolution 返回 |
| via 順序不可達 | PathResolver BFS 串接子路段，自動 backtrack |
| via = startNode 或 endNode | 自動處理（路徑兩次經過，nodeSequence 合併重複） |
| 連續日 endNodeId 相同 | path 為單節點，nodeSequence 不擴展，UI 警示「停留同一節點？」 |
| 拖曳 via 重排 | reactive 觸發 resolveDailyPlans 重算 |
| 移除中間日 | dailyPlans.splice，下一日起點重接，可能 unreachable，由 warning 提示 |
| Migration 舊 plan | Dexie v2 upgrade hook 自動補 |
| Migration 反推不完美（via 為空） | 接受，使用者再編輯時從空白起 |
| Plan 已存後改成不可達日 | save 仍允許，PlanScheduleView 顯示警告區塊 |
| 切換 route（route query 變動） | 重置 draft + editor.reset() |
